# Paper C measurement specification C1

Status: frozen 2026-11-06 before the first formal run; hashes in `paper_c/prereg/MANIFEST`. Pre-specified, not publicly
registered. Pilot, validation and gate traces are not used in the manuscript.

## Questions
- RQ1. What share of the writes a tool issues overwrite an already mapped device page, and how does this depend on the
  amount of stale data, TRIM and the file system?
- RQ2. What does an overwrite replace?
- RQ3. How similar are old and new pages, measured on real bytes, and how does this compare with the content-locality
  levels assumed in prior FTL evaluations?

## Platform
FEMU black-box SSD, 7168 MiB, one guest image for all runs, kernel 6.8.0-147-generic. Tracing with `FEMU_RFTL=trace`
(no page retention; `retained_now` must be 0 in every run). Run script generated by `pilot/make_fs_script.py`.

## Factors
- File system: ext4, XFS, Btrfs (`nodiscard,compress=no` unless TD), F2FS (`nodiscard` unless TD), default mkfs options.
- Condition (5 levels, deletion without TRIM unless stated):
  S0-T0 no stale data; SB-T0 one deleted copy of `/usr`; SC-T0 two deleted copies;
  SC-TD two deleted copies, mounted with discard from mkfs; SC-TF two deleted copies, `fstrim` after the deletion.
- Tool: copynr (`cp -a --reflink=never`), targz, gzipf, git, rsync, sqlite on all file systems, plus copy (`cp -a`) on
  XFS and Btrfs, where it can reflink.
- Replicates: 5 per cell. 26 file-system and tool pairs x 5 conditions x 5 replicates = 650 runs.

## Measures, per run, tool phase only
- Overwrite share = writes with `over` = 1 / all writes.
- Class of the first overwrite of a page in the tool phase, from the block map before deletion:
  freed space (`stale_*`), source tree (`src_*`), file-system metadata (`meta`, `inode`, `node`, `journal`),
  F2FS log segments with no live block (`dead_*`, plus whole 512-page segments of the main area written before the tool
  and holding no page of the block map; found by elimination, node or data not distinguished), unclassified (`other`). Later overwrites of a page in the same phase: `tool`.
- Per class: share of changed bytes above 90 % and at most 10 %; median changed bytes; share with unknown old bytes.
- Delta ratio = zlib-1 size of (old XOR new) / 4096. Compression ratio = zlib-1 size of new page / 4096.
  Saving of delta over compression = per-class sum of (compression size - delta size) / sum of compression size.
- Compared with Rc = 0.20, 0.35, 0.50, the content-locality levels of Delta-FTL (Wu and He, EuroSys 2012).

## Statistics
Mean and 95 % t interval over the 5 replicates of a cell. No test is treated as confirmatory beyond these estimates.

## Validity gates (reported whatever the result)
- G1. Pre-tool written pages outside the block map: at most 5 % per file-system; otherwise reported as unclassified, and
  the class results of that file system are marked accordingly.
- G2. `retained_now` = 0 in every run.
- G3. Trace-only against `FEMU_RFTL=1` on one image: third validation gave 161,242 and 161,067 writes for XFS targz.
- G4. A failed run is rerun once and reported; a tool exit error in `workload.log` is reported per cell.

## Limits to state in the manuscript
Emulated SSD, small device, one source tree, selected tools, default mkfs options, zlib level 1 as the only compressor.

## Run order and infrastructure
650 runs in the fixed random order of `exp/runs.txt` (seed 20261107), two FEMU instances; `versions.txt` records hashes
of the FEMU source, binary and scripts. Estimated about 31 h from the 20 gate runs (56 min).

## Gate results used to fix this design (not manuscript data)
20 of 20 gate runs completed, `retained_now` = 0 in all. In three F2FS runs more than 99.9 % of unmapped pre-tool pages
lie in whole segments without a mapped page, which is why the elimination class above exists.
